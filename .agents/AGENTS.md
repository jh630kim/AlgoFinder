# 프로젝트 AI 코딩 규칙

이 문서는 `AI 코딩규칙.txt`를 바탕으로 작성된 AI 에이전트의 핵심 행동 강령 및 개발 원칙입니다. AI는 아래 규칙을 어떠한 예외도 없이 엄격하게 준수해야 합니다.

## 1. [진행 및 응답 규칙]
- **명시적 지시 전 코딩 절대 금지**: 사용자가 '수정해', '그대로 진행해', '작업시작해'라고 명시적으로 지시하기 전까지 절대로 임의로 소스 코드를 수정/생성하지 않는다. 항상 먼저 구체적인 구현/수정 계획(Plan)을 제시하여 사용자의 사전 승인을 받는다.
- **명시적 지시 전 실행 절대 금지**: 사용자가 '실행해'라고 지시하기 전까지는 테스트 코드 실행이나 시스템 명령 실행을 하지 않는다.
- **질의응답 및 원인 분석 시 수정 금지**:
  - "~할 수 없어?" 문의에는 방법과 방향성만 텍스트로 제시한다.
  - "왜 그렇지?", "원인 파악해", "다시 확인해봐" 문의에는 원인 분석 결과와 제안 수정안만 텍스트로 제시한다.
  - 반영은 사용자가 선택한 이후에 수정을 시작한다.

## 2. [개발 원칙]
- **규칙 1 (역할 분담 및 Thin Client)**: 프론트엔드(HTML/JS)는 데이터 렌더링/입력중계만 담당하며, 모든 비즈니스 연산/가공/검증은 백엔드(Python RESTful API) 객체가 전담한다.
- **규칙 2 (명세 및 주석 표준)**: 모듈/클래스/함수에 한글 독스트링(Docstring) 필수, 주요 조건 분기점에 상세한 인라인 한글 주석을 작성한다.
- **규칙 3 (모듈화 및 크기 제한)**: 파일당 주 객체(Main Class) 1개 중심. 파일 전체 길이 200줄 이내, 개별 메서드 30줄 이내를 원칙으로 한다. 초과 시 분리하거나 사유를 별도 Text로 작성 후 사용자 검토를 받는다.
- **규칙 4 (UI 규격)**:
  - `index.html`에서 접속 기기를 감지하여 분기한다.
  - **PC**: 2분할 레이아웃(좌측 사이드바 너비 220px 고정). `common.css`, `sidebar.html`, `load_sidebar.js` 공통 파일 사용.
  - **모바일**: 상단 헤더 + 하단 탭바 네비게이션 레이아웃. `nav.html`, `load_mobile_nav.js`, `m_common.css` 사용.
  - HTML 내 CSS/JS 참조는 상대경로를 표준으로 한다.
- **규칙 5 (입출력 검증 및 테스트 원칙)**:
  - 테스트용 입출력 데이터는 `tests/fixtures/` 내 JSON/TXT 파일로 분리한다.
  - `test_*.py`에서 `inspect` 모듈을 활용해 요구 매개변수 완전성을 Assert로 검증한다.
  - 정답(Expected)과 실제 출력(Actual)을 1:1로 비교 대조 출력하며, 임의 추측을 금지한다.
- **규칙 6 (배치 및 알림)**: 대량 데이터 처리 및 배치는 `BatchProcessor` 객체가 전담하며(설정은 JSON/Text 정의), 완료/에러 알림은 `DiscordNotifier`를 통해 발송한다.
- **규칙 7 (보안 및 환경)**: 파이썬 웹 프레임워크는 Flask 기반 REST API 사용. DB는 SQLite(`data/app.db`), 보안 정보는 `.env` 파일로 관리.

## 3. [추가 규칙 및 테스트 동기화]
- **새로운 프로젝트 생성**: 항상 `.venv` 가상환경을 프로젝트 폴더 내에 생성하고 진행한다.
- **테스트 분류 및 넘버링**: 백엔드 주요 객체별 1:1 전용 테스트 파일 및 전용 Fixture를 분리한다. 순번(`test_01_...`)을 표기하여 손쉽게 실행을 지시할 수 있도록 한다.
- **소스 변경 시 테스트 동기화**: 원래 소스 변경 시 테스트 코드도 함께 변경하는 것이 원칙이나, AI는 사용자가 **"테스트 코드 작성해"라고 명시적으로 요청할 때만** 해당 단위 테스트 코드 및 픽스처(Fixtures) 데이터를 생성 및 업데이트한다. (명시적 지시 전 임의 생성 금지)

## 4. [프로젝트 표준 폴더 구조]
```text

├── backend/                  # 비즈니스 로직 및 DB 연동 전담 (app, core, models, repositories, services, tests)
├── data/                     # 로컬 DB 저장소 (app.db)
├── frontend/                 # 웹 UI (components, pages, css, js, mobile)
├── .env                      # 보안 환경변수
├── .gitignore                # 제외 목록
└── README.md                 # 설명 문서
```
