# 익일 상승확률 AI 설계안 (2026-08-30)

> 로컬 DB(`data/app.db`)에 이미 적재된 데이터만으로 **"다음 거래일에 오를 확률"** 을 산출하는
> 머신러닝 모델의 구현방안 · 입력 · 학습방법 · 출력을 정의한다.
> 관련 문서: [`순수관행.md`](순수관행.md) · [`전략검토.md`](<(완) 전략검토.md>) · [`진행결과.md`](진행결과.md)

## 1. 요구사항 이해

### 1.1 사용자 요청 재정리

- 현재 로컬 DB에 있는 데이터**만** 사용한다. 외부 신규 수집(재무·컨센서스·뉴스)은 하지 않는다.
- (종목, 날짜) 단위로 **다음 거래일 상승 확률**을 0~100%로 산출하는 AI 모델을 만든다.
- 이번 산출물은 **계획 문서**이며, 코드 작성은 별도 승인 후 진행한다.

### 1.2 현행 `prob_up`과 무엇이 다른가

| 항목 | 현행 `prob_up` | 본 설계(AI 상승확률) |
|---|---|---|
| 산출 방식 | 손튜닝 z-score → 시그모이드 변환 | 과거 데이터로 **학습**한 분류 모델 |
| 확률 의미 | 없음(정렬용 점수를 % 모양으로 표기) | **캘리브레이션된 확률** — "70%" 구간은 실제로 약 70% 상승 |
| 검증 | 없음 | AUC · Brier · ECE · 백테스트 스프레드로 검증 |
| 학습 | 없음 | 시계열 워크포워드 학습·재학습 |

`순수관행.md` §2에서 "확률 미검증 → 점수(백분위) 표기, **캘리브레이션 확률은 후속 옵션**"으로 남겨둔
그 후속 과제를 이 문서가 담당한다. 합성 점수(`composite_score`)는 **횡단면 랭킹**, AI 상승확률은
**절대 확률**로 역할을 분담하며, 서로를 대체하지 않고 병기한다.

### 1.3 사전에 인정하는 한계

- 익일 방향 예측은 신호대잡음비가 매우 낮다. 현실적 기대치는 **AUC 0.52~0.56**이며, 0.60을 넘으면
  누수(look-ahead)를 먼저 의심해야 한다.
- `target_stocks` 632종목은 **현재 시점 기준 정적 유니버스**다(생존편향 존재, 순수관행 §1과 동일 전제).
- 따라서 "정확도 높은 예측기"가 아니라 **"랭킹 상위 구간의 기대수익을 유의하게 끌어올리는 보조 신호"**
  를 목표로 한다.

  → 클래스 불균형이 크지 않아 별도 가중치는 불필요.

### 2.1 발견된 데이터 품질 이슈 (선처리 필수)

- **미조정 가격 이벤트**: 익일 수익률 절대값이 KRX 가격제한폭(±30%, 2015년 이전 ±15%)을 넘는 행이
  **103건** 존재한다(최대 +51,894%). 액면병합·재상장 등으로 가격이 불연속인 구간이며,
  수정주가 처리가 되어 있지 않다.
  → 라벨 생성 시 **|익일수익률| > 상한선 초과 행을 제거**하고, 제거 건수를 학습 리포트에 기록한다.
- **거래정지**: `is_suspended = 1` 6,002행 및 `volume = 0 & high = low` 행은 표본에서 제외.
- **지수 데이터 종료일 불일치**: 지수(20260821)가 종목(20260828)보다 짧다.
  → 지수 피처는 **최근값 forward-fill 후, ffill 일수를 별도 피처/게이트로 관리**한다.

## 3. 구현 방안

### 3.1 기본 전략 — 학습·추론 분리

| | 학습(Training) | 추론(Inference) |
|---|---|---|
| 실행 위치 | **로컬 PC** (전체 `app.db`) | **웹서버** (경량 `app_lite.db`, 최근 2년) |
| 주기 | 월 1회 배치 | 매 거래일 1회 |
| 산출물 | 모델 파일 + 메타 JSON | 예측 테이블 + API 응답 |
| 부하 | 수 분~수십 분 | 수 초 |

PythonAnywhere 배포 제약(CLAUDE.md 규칙 7)상 서버에서 학습을 돌리지 않는다. 서버는 **직렬화된
모델을 로드해 예측만** 수행한다. 경량 DB가 최근 2년(약 480 거래일)을 보유하므로 최장 룩백
252거래일 피처도 서버에서 계산 가능하다.

### 3.2 모듈 구성 (신규 패키지 `backend/app/services/ml/`)

| 모듈 | 주 객체 | 책임 |
|---|---|---|
| `feature_builder.py` | `FeatureBuilder` | OHLCV·지수 → 피처 행렬. **학습·추론 공용**(train/serve skew 차단) |
| `label_builder.py` | `LabelBuilder` | 익일 수익률 → 이진 라벨 + 이상치·정지 종목 필터 |
| `dataset_builder.py` | `DatasetBuilder` | DB 조회 → 피처+라벨 결합 → 학습 데이터셋 |
| `model_trainer.py` | `ModelTrainer` | 워크포워드 분할, 학습, 하이퍼파라미터 탐색 |
| `prob_calibrator.py` | `ProbCalibrator` | Isotonic/Platt 확률 보정 |
| `model_evaluator.py` | `ModelEvaluator` | AUC·Brier·ECE·분위 스프레드·IC 리포트 |
| `prob_predictor.py` | `ProbPredictor` | 모델 로드 → 당일 확률 예측 (서버 전용 경로) |

- CLAUDE.md 규칙 3(파일 200줄 / 메서드 30줄) 준수를 위해 위와 같이 7개로 분할한다.
  초과 발생 시 `docs/size_exceptions.md`에 사유를 기록한다.
- 실행 진입점: 저장소 루트에 `run_ml_train.py` (기존 `run_backtest.py`·`run_data_collection.py`와 동일 패턴).

### 3.3 모델 산출물 규격

```
data/models/
  upprob_20260830.pkl        # 학습된 모델 + 캘리브레이터
  upprob_20260830.meta.json  # 피처 목록/순서, 학습 기간, 하이퍼파라미터, 검증 성능, 데이터 해시
  upprob_latest.json         # 현재 서비스 중인 모델 버전 포인터
```

- `.meta.json`의 **피처 목록·순서를 추론 시 강제 검증**한다(불일치 시 예측 중단 → 폴백).
- 모델 파일은 `.gitignore` 대상(데이터 파생물). 배포 시 `deploy/` 스크립트로 함께 전송.

### 3.4 의존성 및 폴백

- 추가 라이브러리: `lightgbm`, `scikit-learn`.
- `backend/requirements.txt`(로컬 학습용)와 `deploy/requirements-web.txt`(웹 추론용)를 분리 관리한다.
- **서버에 lightgbm 설치가 불가한 경우 대비 폴백 2단계**:
  1. scikit-learn `HistGradientBoostingClassifier`로 대체 학습
  2. 그것도 불가하면 **로컬에서 전 종목 확률을 미리 계산해 테이블로 업로드**(서버는 조회만)
- 모델 파일 부재·로드 실패 시 화면은 기존 **합성 점수 백분위로 자동 폴백**하고, 배지에 `모델 미적용`을 표시한다.

  **성능 기여도만 별도 실험**하고 결과를 리포트에 남긴다. 기본 서비스 모델에는 넣지 않는다.

## 5. 라벨 (예측 대상)

### 5.1 기본 정의

```
y = 1  if  (D+1 종가 / D 종가 - 1) > 0.002   else  0
```

- 임계 0.2%는 왕복 거래비용(수수료+세금) 근사치다. 0%로 두면 "본전 거래"를 상승으로 오분류한다.
- 제외 대상: 거래정지 행, |익일수익률| 가격제한폭 초과 행, 익일 데이터 없는 행(상장폐지·마지막 날).

### 5.2 병행 검토할 대안 라벨

| 안 | 정의 | 채택 이유/시점 |
|---|---|---|
| A. 시장초과 | 종목 익일수익률 − 소속지수 익일수익률 > 0 | 확률이 시장 방향에 끌려다니는 현상 제거. **종목 선별용으로 더 적합할 가능성 높음** |
| B. 체결 정합 | D 종가 정보 → D+1 종가 매수 → D+2 종가 수익 | 순수관행 §1 체결 가정(D-1 신호 → D-0 종가 체결)과 일치시키는 안 |

→ Phase 2에서 기본안/A/B **3종을 모두 학습해 홀드아웃 성능으로 채택안을 결정**한다.
결과는 문서에 기록하고, 화면 문구도 채택 라벨에 맞춰 정확히 쓴다
(예: A 채택 시 "시장 대비 초과 상승 확률"로 표기).

## 6. 학습 방법

### 6.1 데이터 분할 — 시계열 워크포워드

랜덤 K-fold는 **금지**한다(같은 날짜의 다른 종목이 학습·검증에 동시 존재 → 횡단면 누수).

```
[학습 2010~2019] → [검증 2020~2021] → [홀드아웃 2022~2026]
                     ↑ 하이퍼파라미터·캘리브레이션    ↑ 단 한 번만 열어보는 최종 평가
```

- 구간 경계에 **embargo 5거래일**을 두어 라벨 겹침을 제거한다.
- 추가로 **롤링 워크포워드**(학습 5년 → 예측 1년, 1년씩 전진)를 수행해 연도별 성능 안정성을 확인한다.
  특정 연도만 좋은 모델은 채택하지 않는다.

### 6.2 모델

| 순위 | 모델 | 역할 |
|---|---|---|
| 베이스라인 0 | 상수 0.5 예측 | 모든 지표의 하한선 |
| 베이스라인 1 | 로지스틱 회귀(표준화 피처) | 선형 관계로 설명 가능한 부분 측정 |
| 베이스라인 2 | 합성 점수 백분위 → 확률 매핑 | **기존 방식**. 이걸 못 이기면 AI 도입 무의미 |
| 주력 | LightGBM (`objective=binary`) | 비선형·상호작용 포착 |

- 하이퍼파라미터: `num_leaves`, `min_data_in_leaf`, `learning_rate`, `feature_fraction`,
  `bagging_fraction`, `lambda_l2` 소규모 그리드 + 검증 AUC 기준 early stopping.
- 과적합 억제를 우선한다(얕은 트리, 큰 `min_data_in_leaf`, 강한 정규화).

### 6.3 확률 보정 (Calibration)

- LightGBM 원시 출력은 순위는 맞아도 확률로서는 편향된다.
- 검증 구간에서 **Isotonic Regression**(표본 충분하므로 우선), 대안으로 Platt scaling을 적합해
  최종 확률로 변환한다. 캘리브레이터도 모델 파일에 함께 직렬화한다.

### 6.4 평가 지표

| 범주 | 지표 | 채택 기준(홀드아웃) |
|---|---|---|
| 판별력 | ROC-AUC | **≥ 0.53** (미달 시 실전 미적용) |
| 확률 품질 | Brier score, Log loss, **ECE + 신뢰도 곡선** | 베이스라인 0 대비 개선 |
| 랭킹 유용성 | 일별 상위 5종목 익일 평균수익률, 분위 스프레드(Q5−Q1), 일별 Spearman IC 평균/표준편차 | 스프레드 양수 + IC 평균 > 0 |
| 실전 | 기존 백테스트 엔진에 정렬키로 투입 시 CAGR·MDD·승률 | 합성 점수 단독 대비 개선 |

- **정직한 보고 원칙**: 홀드아웃 AUC가 0.53 미만이거나 분위 스프레드가 음수면,
  "성능 미달 — 서비스 미적용" 으로 결론을 명시한다. 지표를 사후에 바꾸지 않는다.

### 6.5 재학습 운영

- 주기: **월 1회**(매월 첫 거래일), 롤링 학습 윈도 최근 10년.
- 재학습 시 직전 모델과 신규 모델을 **동일 최근 구간에서 비교**해, 열세면 승격하지 않는다(챔피언-챌린저).
- 학습 로그와 성능 지표는 `data/models/*.meta.json`에 누적 보관한다.

## 7. 출력

### 7.1 저장 — 신규 테이블 `ml_daily_predictions`

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `date` | VARCHAR(8) | 예측 기준일(D) |
| `symbol` | VARCHAR(20) | 종목코드 |
| `prob_up` | FLOAT | 익일 상승확률(0~100) |
| `prob_pct` | FLOAT | 당일 전 종목 대비 백분위(0~100) |
| `prob_rank` | INTEGER | 당일 등수(1 = 최상위) |
| `model_version` | VARCHAR(20) | 예: `upprob_20260830` |
| `created_at` | DATETIME | 생성 시각 |

- PK: (`date`, `symbol`). 일일 배치가 upsert.
- 저장해 두면 **예측 이력 자체를 사후 검증**할 수 있다(실시간 계산만 하면 검증 불가).

### 7.2 API

| 엔드포인트 | 응답 |
|---|---|
| `GET /api/ml/up-prob?date=YYYYMMDD&limit=N` | `[{code, name, market, prob_up, prob_pct, prob_rank, model_version}]` |
| `GET /api/ml/model-info` | 현재 모델 버전, 학습 기간, 홀드아웃 성능 지표, 마지막 예측일 |
| `POST /api/ml/predict-daily` | 당일 배치 예측 실행(내부용) |

- 신규 Blueprint `backend/app/api/routes_ml.py` (`/api` prefix 공유, CLAUDE.md 규칙 1).

### 7.3 화면 노출

- **투자제안 / 투자제안(모)**: 기존 종목 카드에 `AI 상승확률 62.4%` 배지를 **합성 등수와 나란히** 표기.
  - 확률 구간별 색상(≥60% 강조 / 45~60% 중립 / <45% 회색).
  - 모델 미적용·폴백 상태는 배지에 명시(`모델 미적용`).
- **신규 화면 또는 섹션 "AI 상승확률 TOP 10"**: 당일 확률 상위 10종목을 표로 제시.
  각 행에 확률·백분위·종가·합성 등수를 함께 보여 **두 신호의 일치/불일치를 사용자가 판단**하게 한다.
- **모델 정보 영역**: 화면 하단에 모델 버전·학습 기간·홀드아웃 AUC를 작게 표기해 신뢰 근거를 노출한다.
- **면책 문구 필수**: "통계적 추정치이며 투자 자문이 아닙니다. 손실 책임은 사용자에게 있습니다."

### 7.4 백테스트 연동

- `backtest_engine`의 매수 후보 정렬키에 옵션을 추가한다: `composite`(현행) / `ml_prob` / `blend`.
- `blend`는 두 점수의 백분위 평균. 세 옵션을 동일 기간에 돌려 리더보드에서 비교 가능하게 한다.

| Phase | 내용 | 완료 판정 |

## 10. 승인 요청 사항

코딩 착수 전 다음 3가지에 대한 결정을 요청한다.

1. **라벨 채택 방식** — Phase 2에서 3종을 모두 실험한 뒤 결정할지, 처음부터 특정 안으로 갈지.
2. **수급 피처** — 기본 제외(현 방침 유지)가 맞는지, 실험 대상으로만 둘지.
3. **진행 범위** — Phase 0~2(모델 검증까지)만 먼저 진행할지, Phase 5까지 일괄 진행할지.
