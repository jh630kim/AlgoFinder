# Phase 0 — CI 데이터 파이프라인 최소화

## 1. 요구사항 이해

### 배경
- 웹서버(Render)가 띄우는 화면은 **`투자제안(모바일)`(`/proposal-mobile`) 하나뿐**이다. 나머지 라우트는 302 리다이렉트.
- 웹서버는 데이터를 스스로 수집하지 않는다(`READONLY=1`, `/api/sync*` → 403). 이미지에 구워진 경량 DB `data/app_lite.db`(최근 1년치)를 읽기만 한다.
- 경량 DB는 GitHub Actions(`roll-lite-db.yml`)가 매일 새로 만들어 Release 자산을 교체하고 Render를 재배포한다.
- 그런데 이 CI 롤링이 현재 두 상태 중 하나로만 동작한다.
  - `--skip-collect`: 수집 없이 프루닝/VACUUM만 → 웹 시세가 하루도 전진하지 않음.
  - `--skip-collect` 제거(commit `205de90`): `run_pipeline(stage="all")` 전체 시도 → CI에서 KRX/네이버 차단 → 수집 스텝 통째 실패 → Release 업로드·재배포까지 건너뜀.

### Local PC 트랙은 별개 (이번 변경 대상 아님)
- Local은 메인 대시보드의 **"수급 동기화" 버튼**(`/api/sync` → `run_pipeline(mode="incremental", stage="all")`)으로 데이터를 받는다.
- Local PC는 KRX 로그인 + 네이버 접근이 되므로 **외국인·기관 실제 수급까지 전부** 수집해 20년치 `data/app.db`에 적재한다.
- 이 full DB가 대시보드·백테스트·추천·투자제안 전 화면을 서빙한다.
- Phase 0는 Local의 버튼 동작·수집 방식·DB를 **일절 건드리지 않는다.**

### 목표
- CI의 매일 롤링이 **`투자제안(모바일)` 화면이 실제로 읽는 데이터만**, 그것도 **CI에서 받아지는 것만** 수집하도록 범위를 좁힌다.
- 수집 스텝이 실패하지 않게 하여 Release 교체·Render 재배포가 매일 정상 완료되도록 한다.

### `투자제안(모바일)`이 읽는 데이터와 CI 수집 가능 여부

| 테이블 | 성격 | 용도 | CI 수집 |
|---|---|---|---|
| `all_stock_master` | 정적 | 종목명·업종·시장 표시 | ❌ 안 함 (PC 빌드 lite DB 그대로) |
| `target_stocks` | 정적(유니버스) | `TARGET_SECTORS` 필터로 대상 종목 결정 | ❌ 안 함 (PC 빌드 lite DB 그대로) |
| `market_indices_daily` | 최근 1년 증분 | KOSPI 국면(`kospi_regime`) SSR 주입 | ✅ FDR (Stage 2) |
| `investor_trading_daily` (OHLCV 컬럼) | 최근 1년 증분(타깃만) | 전 지표·신호 산출 | ✅ FDR (경량 Stage 3) |
| `investor_trading_daily` (`is_suspended`) | 〃 | 거래정지일 제외 필터 | ✅ OHLCV로 자동 유추 (기존 로직) |
| `investor_trading_daily` (수급 주체 컬럼) | 〃 | 수급 z-score | ❌ NULL 유지 |

## 2. 할 작업

### 2-1. 수집 파이프라인에 "OHLCV 전용" 단계 문자열 값 추가
- `run_data_collection.run_pipeline()`의 `stage` 인자가 받는 값에 `ohlcv-only`를 추가한다(예: `--stage ohlcv-only`). 별도 불리언 플래그가 아니라 기존 단계 선택 인자의 값으로 다룬다.
- 기본값·기존 값(`all`/`1`/`2`/`3`)은 **현재 동작 유지**(네이버/KRX 수급 포함). `ohlcv-only`를 지정하지 않으면 Local의 기존 흐름과 완전히 동일하다.
- `ohlcv-only`가 지정되면 타깃 종목 수집이 **FDR OHLCV만** 받고 수급 주체 컬럼은 NULL로 적재한다(이미 존재하는 FDR 폴백 경로를 정식 경로로 승격).
- `ohlcv-only`는 Stage 1(마스터/타깃 목록 동기화)을 실행하지 않고, 지수(Stage 2)와 OHLCV 전용 타깃 수집(Stage 3)만 수행한다. CI는 PC가 업로드한 유니버스 목록을 그대로 이어쓴다(목록 드리프트·풀백필 방지).
- Local과 CI가 **같은 코드**를 공유하되, 서로 다른 프로세스에서 다른 인자 값으로, 다른 DB 파일(`app.db` vs `app_lite.db`)에 쓴다. 동시 실행·상태 공유 없음.

### 2-2. 경량 DB 롤링 스크립트 변경
- `deploy/roll_lite_db.py`가 `run_pipeline`을 `stage="ohlcv-only"`로 호출한다.
- 프루닝(365일)·VACUUM·결과 보고는 현행 유지.
- 기존 `--skip-collect` 플래그는 **제거**한다. 롤링은 항상 증분 수집을 시도한다.

### 2-3. 수집 실패 시 경고 및 조치 경로
- `ohlcv-only` 수집이 실패하거나(FDR 장애 등) 새 거래일이 하나도 안 들어온 경우, `roll_lite_db.py`는 조용히 통과하지 않고 **경고를 남기고 비정상 종료 코드**로 끝낸다.
- 워크플로는 이 실패를 감지해 **Discord로 경고 알림**을 보내고, 기존 Release 자산(직전 정상 경량 DB)은 그대로 보존한다(깨진 DB로 재배포하지 않음).
- 개발자는 알림을 받고 수동으로 조치한다: GitHub Actions 재실행, 또는 Local에서 `build_lite_db.py`로 경량 DB 재생성 후 Release 자산 교체.

### 2-4. GitHub Actions 워크플로 수정
- `.github/workflows/roll-lite-db.yml`의 수집 스텝이 `ohlcv-only`로 `roll_lite_db.py`를 실행하도록 변경한다.
- 해당 스텝에서 불필요해진 `KRX_ID` / `KRX_PW` 환경변수 주입을 제거한다.
- 수집 스텝이 실패하면 Release 업로드·Render 재배포는 건너뛰고, `always()` 조건으로 Discord 경고 알림만 발송한다.

> `is_suspended`는 별도 작업 없음. Local·CI 모두 KRX에서 받는 값이 아니라 OHLCV로 유추한다. `market_data_repository.bulk_upsert` → `_is_suspended_row`(거래량 0 & 고가=저가)가 FDR 경로에도 이미 적용되고, `database.py`에 동일 규칙 마이그레이션도 있다. Phase 0에서도 이 규칙을 그대로 쓴다.

# Phase 1 — 백테스트 청산 규칙 + S1b/S1c 폐기

## 6. 요구사항 이해 (Phase 1)

### 원안([전략검토.md](전략검토.md) §7 Phase 1) 대비 조정
- **거래비용 모델**: 이번 Phase 1에서 제외(무시).
- **하드 손절 + 최대 보유일** → **하드 손절/익절만**. 최대 보유일(강제청산)은 하지 않는다. 보유 경과일수(`holding_days`) 화면 표시는 지금처럼 유지.
- **수급 팩터 → CMF 대용**: Phase 1에서 안 함. Phase 2(신호 품질)로 이관. Phase 2에서도 안 풀리면 재논의.
- **지표 확장(샤프·CAGR·손익비 등)**: 제외.
- 신규: **S1b·S1c 전략 폐기** — 5개 화면 전체에서 신호 산출·노출 제거(클래스 코드는 존치).

### 두 축
1. 백테스트 시뮬레이터에 **-5% 손절 / +10% 익절 청산**을 추가한다. 실화면 3개(투자제안·투자제안모·모의투자)엔 이미 `STOP_LOSS_PCT=-5.0` / `TAKE_PROFIT_PCT=10.0`이 있으므로 **손대지 않는다**.
2. <span style="color:red">**S1b·S1c** 를 리더보드·추천·대시보드에서 제거한다. 현재 리더보드/추천은 콤보(9~21)를 쓰지 않고 **단일 전략 8종(`combo_id` 1~8)만** 연산·표시하므로, 실질 효과는 "표시 전략 8종 → 6종".</span>

## 7. 할 작업 (Phase 1)

### 7-1. 백테스트 청산 규칙 추가 (`backtest_engine._simulate_trading`)
- 보유 종목마다 매일 **종가 기준**으로 `pnl = (종가 − 매수가) / 매수가 × 100` 판정.
- 청산 판정은 elif 체인: `pnl <= -5` → 매도(사유 "손절"), 아니면 `pnl >= +10` → 매도(사유 "익절"), 아니면 D-1 `signal_sell` 있으면 → 매도(사유 "전략매도").
- 손절과 익절은 한 종가에서 상호배타라 둘 사이 우선순위는 불필요. 겹칠 수 있는 건 (손절 또는 익절) vs 전략매도뿐이며 앞의 두 사유가 우선.
- 체결가: 갭 하락/급락이어도 **그날 종가** 그대로 체결(비용·슬리피지 무시, 시뮬레이터 기존 D-0 종가 체결 방식과 동일). 예: 매수가 대비 종가 -30%면 -30%로 청산 기록.
- 임계값 상수: 실화면과 동일한 `-5.0 / +10.0`. 가능하면 `proposal_advisor`의 `STOP_LOSS_PCT` / `TAKE_PROFIT_PCT`를 공용 상수로 참조한다. 새 `-7%` 상수는 만들지 않는다.
- 최대 보유일/강제청산은 넣지 않는다. `holding_days`는 지금처럼 매도 로그에만 기록.
- 매매일지(`strategy_trade_logs`) 매도행의 `strategy_tag`에 "손절"/"익절"/"전략매도" 구분을 반영.

### 7-2. S1b·S1c 전략 폐기
- **클래스 파일은 존치**: `s1b_ma_cross_legacy.py`, `s1c_ma_cross_adaptive.py` 삭제하지 않는다.
- `STRATEGY_MAP`에서 `S1b`, `S1c` 키 제거 → `for key in STRATEGY_MAP`을 도는 모든 소비자(추천·차트)가 자동으로 제외됨.
- <span style="color:red">`STRATEGY_COMBOS`에서 단일 콤보 **3(S1b), 4(S1c)** 제거. 콤보 9~21 중 S1b/S1c 포함분(11·12·15·16·20·21)은 **현재 어디서도 연산·표시되지 않는 죽은 정의**라 제거해도 가시적 효과 0(선택적 청소).</span>
- <span style="color:red">`routes_paper.backtest_run`의 재연산 루프 `for c_id in range(1, 9)` → `for c_id in (1, 2, 5, 6, 7, 8)`로 변경. 리더보드에 오르는 전략이 8종 → 6종이 된다.</span>
- <span style="color:red">남는 `combo_id`는 **기존 번호 유지(결번)**: 단일 1·2·5·6·7·8 존속. 재번호하지 않는다(저장된 `strategy_leaderboard`·`strategy_trade_logs`의 `combo_id` 의미 보존).</span>
- 기존에 저장된 리더보드/로그의 폐기 전략(3·4) 행은 다음 백테스트 재실행 시 `clear_all` 후 재연산 대상에서 빠져 자연 소멸.

## 8. 결론이 어떻게 바뀌나 (Phase 1)

### 백테스트 리더보드 (로컬·시뮬레이션 화면)
- **-5% 손절**: 반대 신호까지 -40%도 버티던 손실이 -5%에서 잘림 → 전 전략 **MDD 감소**.
- 평균회귀 계열(S3 볼린저, S4)은 저점 매수 후 추가 하락에 손절당해 **불리**해질 수 있음. 추세 계열(S1, S2)은 손실 조기 차단으로 **유리**.
- **+10% 익절**: 승률·회전은 오르나 큰 추세의 상단을 놓침 → 추세 전략엔 불리.
- 손익 폭이 -5 / +10로 눌리며 **전략 순위가 재배열**된다. 총수익 절대값은 구간에 따라 오르내림.
- <span style="color:red">리더보드에 오르는 전략이 **8종 → 6종**(S1b·S1c 제외). 콤보 9~21은 원래부터 미연산이라 변화 없음.</span>

### 추천 화면 (모의투자·투자제안·투자제안모)
- S1b/S1c가 사유로 잡히던 종목은 **다음 우선 전략**으로 추천되거나 후보에서 빠짐.
- 보유 종목의 손절/익절 배지(-5%/+10%)는 **기존 그대로**(변경 없음).
- 수급 팩터는 이번엔 그대로 두므로, 로컬(수급값)과 웹(NULL) 간 `prob_up` 정렬 순서 미세 차이는 **Phase 2까지 잔존**.

### 메인 대시보드
- 손절/익절 표시 없음(원래 없음, 추가 안 함).
- 차트에서 S1b/S1c 오버레이·선택 항목만 사라짐. 나머지 동일.

## 9. 결정 사항 (Phase 1, 2026-08-29)

1. 거래비용: Phase 1에서 무시.
2. 백테스트 청산: **-5% 손절 / +10% 익절**, 종가 기준 일 1회, `손절→익절→전략매도` elif, 그날 종가 체결. 실화면 상수 재사용(새 `-7%` 상수 안 만듦).
3. 최대 보유일/강제청산: 하지 않음. 보유 경과일수 화면 표시는 유지.
4. S1b·S1c: 폐기(클래스 코드 존치, 신호 산출·노출 제거). 5개 화면 전체 적용.
5. <span style="color:red">폐기 대상: 단일 콤보 3(S1b)·4(S1c). `backtest_run` 루프를 `(1,2,5,6,7,8)`로 축소 → 리더보드/추천 8종 → 6종. `STRATEGY_COMBOS` 11·12·15·16·20·21은 죽은 정의라 청소만(선택). 결번 유지, 재번호 안 함.</span>
6. 수급 팩터 `prob_up` 정리: Phase 2로 이관. Phase 2에서도 안 되면 재논의.
7. 지표 확장: 하지 않음.
8. 메인 대시보드: 손절/익절 표시 없음. 차트 카드명 `기술적 매매지표 (S1~S5)`로, S1b/S1c 선택 항목 숨김.
