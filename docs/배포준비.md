## 2. 단계별 절차

### STEP 0 — 코드 push  *(완료)*
- `master` → `origin/master` 동기화됨 (`a998c19`).

### <span style="color:red">STEP 0-B — Render용 코드 보정  *(Claude가 처리, 승인 시)*</span>
- <span style="color:red">`Dockerfile`: `ARG LITE_DB_URL=""` → 릴리스 URL을 기본값으로. Render는 무료 플랜에서
  Docker build 인자 입력란이 없어, URL을 이미지 빌드에 고정해야 함(공개 고정 URL이라 안전).</span>
- <span style="color:red">`.github/workflows/roll-lite-db.yml`: "Trigger Koyeb redeploy" 스텝 →
  "Trigger Render deploy", Secret `KOYEB_DEPLOY_HOOK_URL` → `RENDER_DEPLOY_HOOK_URL`.</span>
- <span style="color:red">1~2 커밋으로 처리 후 push.</span>

### STEP 1 — GitHub 저장소 설정  *(완료 여부 확인)*
1. 저장소 **Settings → Actions → General**
2. **Workflow permissions** → **Read and write permissions** → Save (Release 자산 갱신용)

### STEP 2 — 최초 경량 DB Release 업로드  *(완료)*
- `lite-db` 태그 릴리스에 `app_lite.db` 첨부 완료.
- 다운로드 URL: `https://github.com/jh630kim/AlgoFinder/releases/download/lite-db/app_lite.db`

### STEP 3 — Turso 준비  *(완료)*
- DB `algofinder-paper` (Tokyo), URL·토큰 발급, 연결 문자열 조립 완료.
- `PAPER_DATABASE_URL` = `sqlite+libsql://algofinder-paper-jhkim.aws-ap-northeast-1.turso.io/?authToken=<TOKEN>&secure=true`
- 로컬 드라이버 테스트는 스킵(Windows+Python 3.14는 `libsql-experimental` 휠 없음 → Render의 Python 3.12 이미지에서 검증).

### STEP 4 — GitHub Secrets  *(부분 완료)*
저장소 **Settings → Secrets and variables → Actions**:

| 이름 | 상태 | 비고 |
|---|---|---|
| `DISCORD_WEBHOOK_URL` | ✅ 등록됨 | 배치 결과 알림 |
| <span style="color:red">`RENDER_DEPLOY_HOOK_URL`</span> | ⬜ <span style="color:red">STEP 6에서 생성 후 등록</span> | <span style="color:red">Actions가 Render 재배포 트리거</span> |
| `TURSO_*` / `KRX_*` | ⬜ 불필요(지금) | 현재 워크플로 미참조 |

### <span style="color:red">STEP 5 — Render Web Service 생성  *(사용자)*</span>

<span style="color:red">Render 무료 웹서비스: 15분 유휴 시 슬립 → 첫 접속 ~50초 콜드스타트(개인용은 무방), 750시간/월 무료.</span>

#### <span style="color:red">5-1. 서비스 생성</span>
1. <span style="color:red">https://dashboard.render.com 가입/로그인 (GitHub 계정)</span>
2. <span style="color:red">우측 상단 **New +** → **Web Service**</span>
3. <span style="color:red">**Build and deploy from a Git repository** → Next</span>
4. <span style="color:red">GitHub 연결 → `jh630kim/AlgoFinder` 선택 → **Connect**</span>

#### <span style="color:red">5-2. 기본 설정</span>
| <span style="color:red">항목</span> | <span style="color:red">값</span> |
|---|---|
| <span style="color:red">Name</span> | <span style="color:red">`algofinder` (→ `https://algofinder.onrender.com`)</span> |
| <span style="color:red">Region</span> | <span style="color:red">**Singapore** (한국서 가장 가까움)</span> |
| <span style="color:red">Branch</span> | <span style="color:red">`master`</span> |
| <span style="color:red">Language / Runtime</span> | <span style="color:red">**Docker** (루트 `Dockerfile` 자동 감지)</span> |
| <span style="color:red">Dockerfile Path</span> | <span style="color:red">`./Dockerfile` (기본값)</span> |
| <span style="color:red">Instance Type</span> | <span style="color:red">**Free**</span> |

#### <span style="color:red">5-3. Health Check</span>
- <span style="color:red">**Health Check Path** = `/proposal-mobile`</span>
  <span style="color:red">(`/` 는 web 프로필에서 302라 실패 가능 → 200 나오는 경로로)</span>

#### <span style="color:red">5-4. 환경변수 (Environment Variables)</span>
| <span style="color:red">Key</span> | <span style="color:red">Value</span> |
|---|---|
| <span style="color:red">`APP_PROFILE`</span> | <span style="color:red">`web`</span> |
| <span style="color:red">`READONLY`</span> | <span style="color:red">`1`</span> |
| <span style="color:red">`FLASK_DEBUG`</span> | <span style="color:red">`False`</span> |
| <span style="color:red">`DATABASE_URL`</span> | <span style="color:red">`sqlite:///./data/app_lite.db`</span> |
| <span style="color:red">`PAPER_DATABASE_URL`</span> | <span style="color:red">`sqlite+libsql://algofinder-paper-jhkim.aws-ap-northeast-1.turso.io/?authToken=<TOKEN>&secure=true` (따옴표 없이 전체 붙여넣기)</span> |

- <span style="color:red">**`PORT` 는 넣지 않는다** — Render가 자동 주입(보통 10000), Dockerfile CMD `${PORT:-8000}` 가 처리.</span>
- <span style="color:red">`PAPER_DATABASE_URL` 은 토큰 포함이라 민감 → Render는 기본이 안전 저장이므로 그대로 입력 OK.</span>

#### <span style="color:red">5-5. 생성 & 로그</span>
5. <span style="color:red">**Create Web Service** 클릭 → 자동으로 첫 빌드·배포 시작</span>
6. <span style="color:red">**Logs** 탭 확인:</span>
   - <span style="color:red">빌드: `pip install -r requirements-web.txt` 에서 `sqlalchemy-libsql` / `libsql-experimental` 이 **휠로** 설치되는지 (Turso 드라이버 첫 실검증)</span>
   - <span style="color:red">빌드: `curl -fSL ... app_lite.db` 성공 라인 (STEP 0-B의 기본값 URL 사용)</span>
   - <span style="color:red">런타임: `gunicorn ... app:app`, `Listening at 0.0.0.0:10000`</span>
   - <span style="color:red">런타임: `DatabaseManager` 초기화 시 Turso 연결 에러 없는지</span>
7. <span style="color:red">상태가 **Live** (초록) 되면 `https://algofinder.onrender.com/` 접속 → `/proposal-mobile` 로 이동하는지</span>

### <span style="color:red">STEP 6 — Deploy Hook 생성 → Secret 등록  *(사용자)*</span>
1. <span style="color:red">Render 서비스 → **Settings** → **Deploy Hook** 항목의 URL 복사
   (형식: `https://api.render.com/deploy/srv-xxxxx?key=yyyyy`)</span>
2. <span style="color:red">GitHub 저장소 → Settings → Secrets and variables → Actions → **New repository secret**
   → Name `RENDER_DEPLOY_HOOK_URL`, Secret = 복사한 URL → Add secret</span>
3. <span style="color:red">(참고) Render는 `master` push 시 자동 재배포도 되지만, **롤링 경량 DB는 Release 자산만 바뀌고
   코드 push가 없으므로** 이 훅으로 강제 재배포가 필요하다.</span>

### STEP 7 — Actions 파이프라인 1회 검증  *(사용자)*
1. GitHub **Actions → roll-lite-db → Run workflow** (`workflow_dispatch`)
2. 확인:
   - `Download current lite DB from Release` 성공
   - `Roll (incremental collect + prune)` 이 `--skip-collect` 로 프루닝/VACUUM만 수행
   - `Upload lite DB to Release` 로 `lite-db` 자산 갱신
   - <span style="color:red">`Trigger Render deploy` 가 `RENDER_DEPLOY_HOOK_URL` 로 POST → Render에서 새 배포 시작</span>
   - `Discord notify` 로 `roll-lite-db: success` 수신

### STEP 8 — 동작 확인  *(사용자)*
- [ ] <span style="color:red">`https://algofinder.onrender.com/`</span> → **투자제안 모바일 화면**으로 이동(302)
- [ ] <span style="color:red">`/backtest`, `/recommendation`, `/proposal`</span> → 모바일로 리다이렉트
- [ ] 모바일 화면에 **동기화 버튼 없음**, `POST /api/sync` → 403
- [ ] 추천 조회·차트·매수/매도 모달 정상, 보조 차트가 기준일까지만 그려짐
- [ ] 휴대폰 접속 → **홈 화면에 추가(PWA)**
- [ ] 휴대폰에서 매수 1건 → <span style="color:red">Turso 대시보드 `algofinder-paper` → Tables 에 `paper_*` 3개 생성</span> → PC 로컬 앱 투자제안에서도 보임(로컬 `.env`에 `PAPER_DATABASE_URL` 넣은 경우)
- [ ] **⬇️ 내보내기** → JSON 수신 / 일부 수정 후 **⬆️ 불러오기** → 확인 모달 → 백업 자동 다운로드 → 반영

### STEP 9 — 로컬 `.env` 정리  *(사용자, 선택)*
- PC 로컬 앱도 `prop` 을 Turso와 공유하려면 로컬 `.env` 에 `PAPER_DATABASE_URL` 추가 후 앱 재기동.
  - <span style="color:red">단, Windows+Python 3.14 `.venv` 에서는 `sqlalchemy-libsql` 설치가 안 되므로
    로컬 공유가 필요하면 `.venv` 를 Python 3.12로 다시 만들어야 함.</span>
- 넣지 않으면 로컬 `prop` 은 계속 `data/app.db` 사용(현재와 동일).

## 4. 자주 나오는 문제

| 증상 | 원인 / 조치 |
|---|---|
| <span style="color:red">빌드에서 `libsql-experimental` 컴파일 시도/실패</span> | <span style="color:red">Render 런타임이 Docker가 맞는지 확인(Python 네이티브 빌드로 잡히면 안 됨). 이미지 base는 `python:3.12-slim` → cp312 휠 존재</span> |
| <span style="color:red">빌드에서 `curl ... app_lite.db` 실패</span> | <span style="color:red">STEP 0-B의 Dockerfile 기본 URL 오타 또는 Release 자산 삭제. `releases/download/lite-db/app_lite.db` 접근 확인</span> |
| 배포는 됐는데 `/` 가 200 | `APP_PROFILE` 이 `web` 로 안 들어감. Render 환경변수 오타 |
| <span style="color:red">첫 접속이 30~60초 걸림</span> | <span style="color:red">Render 무료 슬립→콜드스타트. 정상. 자주 쓰면 유료 인스턴스나 외부 핑</span> |
| 가상매매가 재배포마다 사라짐 | `PAPER_DATABASE_URL` 미설정(Turso 폴백 중) |
| `sqlite+libsql` 연결 에러(런타임) | Turso URL/토큰 오타, 또는 토큰 만료. Turso 대시보드에서 토큰 재발급 후 Render 환경변수 교체 |
| Actions `Upload lite DB` 권한 오류 | STEP 1의 Workflow permissions = Read and write 미적용 |
| Discord 알림 안 옴 | Secret `DISCORD_WEBHOOK_URL` 미등록 (로컬 `.env` 와 별개) |

## 5. 권장 진행 순서 (한눈에)

```
STEP 0    Claude: git push                         ✅ 완료
STEP 0-B  Claude: Dockerfile LITE_DB_URL 기본값 + roll-lite-db.yml Render화   ← 승인 대기
STEP 1    GitHub: Actions 권한 Read and write       (확인)
STEP 2    GitHub: Release(lite-db)에 app_lite.db    ✅ 완료
STEP 3    Turso : 가입·DB·토큰                       ✅ 완료
STEP 4    GitHub: DISCORD_WEBHOOK_URL Secret        ✅ 완료
STEP 5    Render: Web Service 생성 + Docker + 환경변수 5개 + Health Check /proposal-mobile
STEP 6    Render: Deploy Hook 생성 → GitHub Secret RENDER_DEPLOY_HOOK_URL
STEP 7    GitHub: Actions 수동 실행 1회
STEP 8    확인  : 접속·리다이렉트·PWA·Turso 테이블·JSON 백업
STEP 9    로컬  : (선택) .env 에 PAPER_DATABASE_URL  (Py3.12 venv 필요)
```
