# 전략 검토 및 CI 데이터 최소화 방안 (2026-08-29)

> 배경: Render 배포 후 `roll-lite-db` 워크플로에서 `--skip-collect` 를 제거해 CI 자동 수집을 시도했으나,
> GitHub Actions에서 KRX/네이버 접근이 막혀 수급 주체별 데이터를 못 받는 것이 확인됨. 이에 따라
> "추천에 필요한 최소 정보만 CI에서 받는" 원래 계획으로 되돌리고, 전략의 수급 팩터도 재검토함.

---

## 1. CI(GitHub Actions)에서 받을 수 있는 것 / 없는 것

이번 워크플로 실행 로그로 확인:

| 소스 | CI에서 | 받는 내용 |
|---|---|---|
| **FDR (FinanceDataReader)** | ✅ 됨 | OHLCV(시·고·저·**종가**·거래량), 지수·환율 |
| **pykrx (KRX 직접)** | ❌ | 로그인 실패 + 데이터센터 IP 차단. `지수 티커 1028 수집 실패` 반복 |
| **네이버 스크래핑** | ❌ | 전 종목 "0건" → FDR 폴백 |

→ **CI에서 매일 받을 수 있는 것 = 종가 포함 OHLCV + 지수. 수급 주체별(외국인·기관·개인)은 불가.**

## 2. 현재 전략이 실제로 쓰는 입력 (OHLCV·지수 외)

`backtest_engine.load_market_dataframe` + 전략 코드 기준.

| 정보 | 출처 | 용도 | CI |
|---|---|---|---|
| `foreigner_net_buy`, `institution_net_buy` | `investor_trading_daily` | `calc_investor_z_score` → `prob_up` (가중 0.4, **부호만**, 2일 연속) | ❌ |
| `is_suspended` | 〃 | `load_market_dataframe` 가 `is_suspended==0` 필터 (거래정지일 제외) | ⚠️ FDR엔 없음 → 유추(거래량 0 & 고가=저가) |
| `name`, `sector` | `all_stock_master` | 화면 표시, 업종 필터 | 정적 — **PC 업로드분** |
| 타깃 종목 목록 | `target_stocks` | 대상 종목 결정 | 정적 — **PC 업로드분** |

- `personal_net_buy` 등 나머지 수급 컬럼: 로드만 되고 전략은 사용 안 함.
- 신호 산출 자체는 **100% OHLCV 파생**(이동평균·볼린저·RSI·거래량비율·캔들).

## 3. 못 받는 정보(수급 주체별)를 어느 전략이 쓰는가

`calc_investor_z_score` 는 **모든 전략**(S1, S1a, S1b, S1c, S2, S3+S3a, S4+S4a, S5)이 호출한다.
다만 **매수/매도 신호 자체에 영향을 주는 곳은 두 곳뿐**:

| 전략 | prob_up에 수급 반영 | 매수 **신호**가 수급에 의존? |
|---|---|---|
| S1 / S1a / S2 / S3 / S3a / S4 / S4a / S5 | O | ✗ — 추천 종목 불변, `prob_up` 숫자만 밋밋해짐 |
| **S1b** | O | ✅ `signal_buy &= (prob_up >= 55.0)`. 수급 NULL이면 prob_up이 최대 ~10%p 하락 → 원래 통과했을 매수가 탈락 |
| **S1c** | O | ✅ (상승추세 구간만) 상승추세 → S1b 신호 계승. 횡보 → S1a(순수 기술적) |

→ "전체 수급량 대용치"가 정말 필요한 지점은 **S1b/S1c의 `prob_up >= 55` 게이트** 하나.

## 4. 전체 수급량을 OHLCV로 대체 가능한가

- **실제 순매수 금액(원)**: OHLCV로 **불가**. 매수/매도량 구분·투자자 유형은 거래소(체결/집계) 데이터 필요.
- **방향성 있는 "자금 유입 강도" 대용치**: OHLCV만으로 계산 가능.

| 지표 | 계산 | 비고 |
|---|---|---|
| 거래대금 = 종가×거래량 | 단순 | 관심도(방향 없음) |
| OBV | 상승마감일 +V, 하락마감일 −V 누적 | 매집/분산 |
| ADL | `((C−L)−(H−C))/(H−L) × V` 누적 | 일중 종가 위치 기반 매수압력 |
| **CMF (Chaikin Money Flow)** | N일 ADL 자금흐름합 ÷ N일 거래량합 (−1~+1) | **"순수급 강도"의 OHLCV 버전에 가장 근접** |
| MFI | typical price×V 기반 RSI (0~100) | 거래량 가중 RSI |

### 대체안 (형태 유지)
`calc_investor_z_score` 현재: "외국인+기관 2일 연속 동시매수 → +1.5 / 동시매도 → −1.5 / 그 외 0".
입력만 교체:
- **CMF(20)** (또는 ADL 5일 기울기) 계산
- 2일 연속 CMF > +임계값 → **+1.5**, 2일 연속 CMF < −임계값 → **−1.5**, 그 외 0

### 주의
- CMF/ADL은 외국인·기관 실제 수급과 **다른 신호**(상관 중간). S1b/S1c 추천이 KRX 데이터 버전과 달라짐 — 재현이 아니라 대체.
- **하이브리드 권장**: 주체별 수급 컬럼이 있으면(과거 PC 수집분) 기존 로직, 없으면(CI 갱신 최근분) CMF 대용 → 로컬 백테스트 결과 불변.

## 5. 참고 — 이 프로젝트의 "Z-Score"

- 통계적 Z-score `(x−평균)/표준편차` 는 퀀트에서 표준(평균회귀, 볼린저, 팩터 랭킹, 피처 정규화).
- 이 코드의 `z_core`·`z_investor` 는 **이름만 Z-score**:
  - `z_core` (S1) = `괴리율 / 1.5` — 지표를 상수로 나눈 스케일 값
  - `z_investor` = 조건 만족 시 하드코딩 `±1.5 / 0` 플래그
- 실제로는 "표준화된 입력 → 시그모이드 점수 결합"(로지스틱 회귀 스타일) 패턴. 설계는 합리적이나 입력이 진짜 롤링 z-score는 아님.

## 6. 일반적인 퀀트 전략과의 차이

### A. 알파/신호 설계
| 현재 | 일반 관행 |
|---|---|
| 종목별 이벤트 트리거(패턴 뜨면 매수) | 횡단면 팩터 랭킹(전 종목 정렬 → 상위 롱). 이벤트 기반은 저샤프·국면 의존 |
| `prob_up` 을 종목 단독 계산 | 후보를 유니버스 대비 상대평가 |
| z_core 스케일 상수가 매직넘버(`/1.5`, `/15`, `/25`…) | 롤링 표준화 또는 회귀/최적화로 가중치 학습 |
| `prob_up` 을 "확률"이라 부르지만 미검증(uncalibrated) | 실현 전방수익률에 로지스틱/부스팅 적합 + 캘리브레이션 곡선 |
| S1 독스트링은 "60일선 정배열"인데 코드엔 `sma60` 미사용 | 문서=코드 일치 |
| 유니버스 = **현재** 지수 멤버로 과거 백테스트 | 시점(point-in-time) 유니버스 → 생존편향 제거 |
| 수급 팩터가 2진 플래그 | 연속값, 거래량 정규화, 다일 감쇠 |

### B. 리스크 관리 (가장 큰 공백)
| 현재 | 일반 관행 |
|---|---|
| **백테스트 시뮬에 손절·시간청산 없음**. 반대 신호까지 −40%도 버팀 | 하드 스톱(ATR·%) + 최대 보유일 |
| 균등 비중 고정 | 변동성 타깃팅(ATR 역가중) — 포지션별 리스크 균등 |
| 포트폴리오 레벨 통제 없음 | 섹터/상관 한도, 일일 손실 한도·킬스위치 |
| MDD 표시만 | 임계 초과 시 자동 디리스킹 |

### C. 백테스트 현실성
| 현재 | 일반 관행 |
|---|---|
| **수수료·세금·슬리피지 0** | 한국: 매도세 0.18% + 수수료 + 슬리피지. 3슬롯 스윙이면 연 5~15% drag |
| 파라미터 손튜닝(0.14, 55%, 1.5, 1.8배…) | 인샘플 선택 → 아웃오브샘플만 보고, 워크포워드 |
| 지표: 총수익·승률·MDD·거래수 | + 샤프/소르티노, CAGR, 노출시간, 손익비, 프로핏팩터, 회전율, 비용 drag, KOSPI 대비 초과수익 |
| 승률 강조 | 손익비 없는 승률은 오해 유발 |

### D. 콤보
| 현재 | 일반 관행 |
|---|---|
| 콤보 = 멤버 신호의 **OR** | 가중·컨펌("3중 2 동의 시만"). 무상관 OR은 회전율만 증가 |

## 7. 개선 계획

### Phase 0 — CI 데이터 파이프라인 최소화 (즉시)
- `roll_lite_db.py` 에 수집 단계 제한 옵션 추가(예: `--stage 23` 또는 `--ohlcv-only`).
- CI는 **Stage 1(마스터/타깃) 제외** — 경량 DB의 PC 업로드분 목록 그대로 사용(풀 백필·목록 드리프트 방지).
- CI는 **Stage 2(지수, FDR)** + **경량 Stage 3(FDR OHLCV만, 증분)** 만.
- `investor_trading_daily` 의 수급 컬럼은 CI 갱신분에서 NULL 유지.
- `.github/workflows/roll-lite-db.yml` 를 새 옵션에 맞게 수정.

### Phase 1 — 결론을 바꾸는 것 (필수)
1. **거래비용 모델** — 백테스트 `_simulate_trading` 에 매수/매도 수수료 + 매도세 + 슬리피지(bps 파라미터).
2. **하드 손절 + 최대 보유일** — 청산 조건에 `−X%` 스톱, `N일 경과` 강제청산. (`holding_days` 는 이미 증가만 하고 미사용 → 연결)
3. **수급 팩터 → CMF(20) 대용** — `calc_investor_z_score` 하이브리드(주체별 있으면 기존, 없으면 CMF). 로컬 백테스트 불변, 웹 최근분만 대용.
4. **지표 확장** — 샤프, CAGR, 손익비, 회전율, 노출시간, KOSPI 벤치마크 대비. 리더보드 노출.

### Phase 2 — 신호 품질
5. **z_core 진짜 표준화** — 매직상수 → 롤링 z-score(국면·종목 변동성 적응).
6. **S1 문서/코드 정합** — `sma60` 정배열 필터를 실제로 넣을지, 독스트링을 고칠지 결정.
7. **prob_up 캘리브레이션** — 전방 5일 수익률 대비 로지스틱 회귀 재적합 + 캘리브레이션 곡선. (또는 "확률" 표기를 "점수"로 하향)
8. **콤보 로직** — OR → "K중 M 동의" 옵션.

### Phase 3 — 구조 (선택, 큼)
9. **횡단면 랭킹 모드** — 이벤트 필터 통과 종목을 유니버스 대비 팩터 z-score로 재정렬.
10. **시점 유니버스** — `target_stocks` 이력 테이블 도입, 생존편향 제거.
11. **변동성 타깃 사이징**, 포트폴리오 리스크 한도.

## 8. 결정 필요 사항

1. **범위**: Phase 0 + Phase 1만? Phase 2까지? 전체?
2. **수급 대용치**: CMF(20) 기반으로 OK? (아니면 ADL 기울기 / 거래대금 z-score)
3. **수급 로직 적용**: 하이브리드(백테스트 불변) vs 전면 교체(백테스트도 CMF)
4. **손절 기준**: 고정 %(예: −7%) vs ATR 배수?
5. **백테스트 비용 기본값**: 한국 표준(매도세 0.18% + 수수료 0.015%×2 + 슬리피지 ~10bps)으로 박기?
6. **S1 sma60 필터**: 코드에 추가(신호 더 엄격) vs 독스트링만 수정?
7. Phase 1은 **로컬 백테스트 결과가 바뀜**(비용·손절 반영). 목적이 맞는지 확인.

## 9. 참고 — 현재 매매 시뮬레이터 규칙 (backtest_engine `_simulate_trading`)

- D-1 신호 → D-0 종가 체결.
- 슬롯 = 백테스트 3개 / 투자제안 5개. 균등 배분(`equity / max_slots`).
- 매도: **`signal_sell` 발생 시에만** (손절·시간청산 없음).
- 매수: `signal_buy` 종목을 `prob_up` 내림차순 정렬 → 빈 슬롯 수만큼 상위 선택.
- 수수료·세금·슬리피지 미반영.
