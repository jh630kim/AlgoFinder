# 배포 실행 가이드 — 사용자 단계별 (Koyeb + 경량 DB + Turso)

> 설계 근거: [`web_deploy_plan.md`](web_deploy_plan.md) · 실행 요약: [`../deploy/README.md`](../deploy/README.md)
> 이 문서는 **"이제 사용자가 무엇을 눌러야 하는가"** 만 순서대로 정리한 것이다.

---

## 0. 현재 상태

| 구분 | 상태 |
|---|---|
| 코드·스크립트·Dockerfile·Actions 워크플로 | ✅ 구현·로컬 검증 완료 (`web_deploy_plan.md` §9) |
| 로컬 `web` 프로필 스모크 | ✅ `/` → `/proposal-mobile` 302, `/backtest` 302, `POST /api/sync` 403, 추천 연산 정상(경량 DB로 17건) |
| 경량 DB `data/app_lite.db` | ✅ 방금 재생성 (20.3 MB, 컷오프 20250828, itd 148,232행) |
| GitHub 원격 push | ❌ **미완** — `master`가 `origin/master`보다 **10 커밋 앞섬** |
| Turso / Koyeb / GitHub Secrets / Release | ❌ 사용자 계정 작업 미착수 |

원격: `https://github.com/jh630kim/AlgoFinder.git`

## 1. 역할 분담

### Claude가 대신 가능 (지시하면 수행)
- **코드 push** (`git push origin master`) — 아웃바운드 작업이라 **승인 후** 실행
- 경량 DB(`data/app_lite.db`) 재생성·검증 (완료)
- `gh` CLI 기반 Release 생성·업로드 **명령 스크립트 작성** (실행은 사용자 인증 필요)
- `PAPER_DATABASE_URL` 등 환경변수 문자열을 사용자 값에 맞춰 조립해 주기
- (선택) PWA 아이콘 PNG 생성 + `manifest.webmanifest`에 `icons` 추가
- `requirements-web.txt`의 `sqlalchemy-libsql` 주석 해제 (Turso 쓸 때)

### 사용자만 가능 (계정·브라우저 로그인 필요)
- GitHub 저장소 설정(Actions 권한), Secrets 등록
- GitHub Release에 실제 파일 업로드 (또는 로컬에서 `gh auth login` 후 스크립트 실행)
- Turso 가입·DB 생성·토큰 발급
- Koyeb 가입·앱 생성·환경변수 입력·배포 훅 생성
- 최종 동작 확인(휴대폰 접속, PWA 추가 등)

## 2. 단계별 절차

### STEP 0 — 코드 push  *(Claude 대행 가능)*
- **무엇**: 미푸시 10커밋을 `origin/master`로 올린다. Koyeb는 GitHub에서 빌드하므로 이게 선행 필수.
- **명령**:
  ```bash
  git push origin master
  ```
- **완료 기준**: GitHub에서 `Dockerfile`, `.github/workflows/roll-lite-db.yml`, `deploy/` 가 보인다.
- 진행 중인 소스 수정분(차트 기준일 제한 등)은 별도 커밋 후 함께 push 여부를 결정.

### STEP 1 — GitHub 저장소 설정  *(사용자)*
1. 저장소 **Settings → Actions → General**
2. **Workflow permissions** → **Read and write permissions** 선택 → Save
   - Release 자산을 Actions가 갱신하려면 필요.
3. Actions 탭이 활성인지 확인(비활성이면 활성화).

### STEP 2 — 최초 경량 DB를 Release로 업로드  *(사용자 / Claude가 스크립트 제공)*
- Koyeb 첫 빌드가 `LITE_DB_URL`에서 DB를 받아오므로, `lite-db` 태그 Release에 파일이 먼저 있어야 한다.
- 로컬에 GitHub CLI(`gh`)가 있고 `gh auth login` 이 돼 있으면:
  ```bash
  gh release create lite-db --notes "rolling lite db (initial)" || true
  gh release upload lite-db data/app_lite.db --clobber
  ```
- CLI가 없으면: GitHub 웹 → **Releases → Draft a new release** → Tag `lite-db` → `data/app_lite.db` 를 첨부 → Publish.
- **완료 기준**: `https://github.com/jh630kim/AlgoFinder/releases/download/lite-db/app_lite.db` 가 받아진다.
- 이 URL이 곧 Koyeb 빌드 인자 `LITE_DB_URL` 값이다.

### STEP 3 — Turso 준비  *(사용자, 선택이지만 권장)*
> Turso를 **쓰지 않으면**: 투자제안 가상매매(`prop`)가 Koyeb 컨테이너의 경량 DB에 쓰이고 **재배포 때마다 초기화**된다. JSON 내보내기로만 백업 가능.
> Turso를 **쓰면**: `prop` 기록이 PC·휴대폰·재배포와 무관하게 영속.

1. https://turso.tech → GitHub로 가입
2. DB 1개 생성, 리전은 서울과 가까운 곳(예: `nrt` 도쿄)
3. **Database URL**(`libsql://<name>-<org>.turso.io`)와 **auth token** 발급 → 안전한 곳에 보관
4. SQLAlchemy 연결 문자열 형식 (드라이버: `sqlalchemy-libsql`):
   ```
   sqlite+libsql://<name>-<org>.turso.io/?authToken=<TOKEN>&secure=true
   ```
   - 이 문자열이 `PAPER_DATABASE_URL` 값이다. (정확한 조립은 Claude에게 URL·토큰 주면 만들어 줌 — **토큰은 민감정보이므로 필요 시 마스킹**해서 공유)
5. `deploy/requirements-web.txt` 의 `sqlalchemy-libsql` 주석을 해제하고 커밋·push (Claude 대행 가능).

### STEP 4 — GitHub Secrets 등록  *(사용자)*
저장소 **Settings → Secrets and variables → Actions → New repository secret**:

| 이름 | 값 | 용도 |
|---|---|---|
| `KOYEB_DEPLOY_HOOK_URL` | STEP 6에서 생성 | Actions가 배포 재트리거 |
| `DISCORD_WEBHOOK_URL` | 기존 `.env` 값 재사용 | 배치 결과 알림 |
| `KRX_ID` / `KRX_PW` | KRX 계정 | (지금은 미사용 — 워크플로가 `--skip-collect`) |
| `TURSO_DATABASE_URL` | STEP 3의 URL | (현재 워크플로는 직접 사용 안 함, 향후 대비) |
| `TURSO_AUTH_TOKEN` | STEP 3의 토큰 | 〃 |

> 현재 `roll-lite-db.yml` 은 프루닝/VACUUM만 하므로 필수 Secret은 `KOYEB_DEPLOY_HOOK_URL`, `DISCORD_WEBHOOK_URL` 둘뿐. 나머지는 넣어두면 이후 수집 활성화 시 재사용.

### STEP 5 — Koyeb 앱 생성  *(사용자)*
1. https://koyeb.com → GitHub로 가입 (결제수단 등록 요구 여부 확인)
2. 기존에 배포해 둔 다른 서비스가 있으면 삭제
3. **Create App → GitHub** → 저장소 `AlgoFinder`, 브랜치 `master`
4. **Builder: Dockerfile** (경로 `Dockerfile`, 저장소 루트)
5. **Build arguments**:
   | 키 | 값 |
   |---|---|
   | `LITE_DB_URL` | `https://github.com/jh630kim/AlgoFinder/releases/download/lite-db/app_lite.db` |
6. **Environment variables**:
   | 키 | 값 |
   |---|---|
   | `APP_PROFILE` | `web` |
   | `READONLY` | `1` |
   | `FLASK_DEBUG` | `False` |
   | `DATABASE_URL` | `sqlite:///./data/app_lite.db` |
   | `PAPER_DATABASE_URL` | STEP 3의 `sqlite+libsql://...` (Turso 미사용 시 **비워둠**) |
   - `PORT` 는 Koyeb이 자동 주입(Dockerfile이 `${PORT:-8000}` 처리). 수동 입력 불필요.
7. **Instance**: Free (eco/nano), 리전 선택
8. **Health check**: HTTP, Path = `/proposal-mobile` , Port = 8000 (또는 Koyeb 주입 포트)
9. Deploy 실행 → **Build 로그 + Runtime 로그** 확인
   - Build 로그에 `curl ... app_lite.db` 성공 라인이 보여야 함.

### STEP 6 — 배포 훅 생성 → Secret에 등록  *(사용자)*
1. Koyeb App → **Settings → Deploy webhook** (또는 Service 설정) → URL 생성 → 복사
2. GitHub Secret `KOYEB_DEPLOY_HOOK_URL` 에 붙여넣기 (STEP 4 표 참고)

### STEP 7 — Actions 파이프라인 1회 검증  *(사용자)*
1. GitHub **Actions → roll-lite-db → Run workflow** (`workflow_dispatch`)
2. 확인:
   - `Download current lite DB from Release` 성공 (STEP 2 자산을 받음)
   - `Roll (incremental collect + prune)` 이 `--skip-collect` 로 프루닝/VACUUM만 수행
   - `Upload lite DB to Release` 로 `lite-db` 자산 갱신 (수정 시각 변경)
   - `Trigger Koyeb redeploy` 가 훅 호출 → Koyeb에서 새 빌드 시작
   - `Discord notify` 로 `roll-lite-db: success` 메시지 수신

### STEP 8 — 동작 확인  *(사용자)*
- [ ] `https://<앱>.koyeb.app/` → **투자제안 모바일 화면**으로 이동(302)
- [ ] `https://<앱>.koyeb.app/backtest`, `/recommendation`, `/proposal` → 모바일로 리다이렉트
- [ ] 모바일 화면에 **동기화 버튼 없음**, `POST /api/sync` → 403
- [ ] 추천 조회·차트·매수/매도 모달 정상, 보조 차트가 기준일까지만 그려짐
- [ ] 휴대폰 접속 → **홈 화면에 추가(PWA)**
- [ ] (Turso 사용 시) 휴대폰에서 매수 1건 → PC 로컬 앱 투자제안에서도 보임
- [ ] **⬇️ 내보내기** → JSON 파일 수신, 내용 확인
- [ ] 파일 일부 수정 → **⬆️ 불러오기** → 확인 모달 → 백업 자동 다운로드 → 반영 확인

### STEP 9 — 로컬 `.env` 정리  *(사용자, 선택)*
- PC 로컬 앱도 `prop` 을 Turso와 공유하려면 로컬 `.env` 에 동일한 `PAPER_DATABASE_URL` 추가 후 앱 재기동.
- 넣지 않으면 로컬 `prop` 은 계속 `data/app.db` 사용(현재와 동일).

## 3. 환경변수 레퍼런스

| 변수 | 로컬(full) | Koyeb(web) | 비고 |
|---|---|---|---|
| `APP_PROFILE` | 미설정/`full` | `web` | web이면 PC 4페이지 → `/proposal-mobile` 302 |
| `READONLY` | `0` | `1` | `/api/sync*` 403. 가상매매 쓰기는 허용 |
| `DATABASE_URL` | 미설정(→`data/app.db`) | `sqlite:///./data/app_lite.db` | 시세 DB |
| `PAPER_DATABASE_URL` | 선택(Turso) | Turso `sqlite+libsql://...` | 미설정 시 `prop`도 `DATABASE_URL` 폴백 |
| `FLASK_DEBUG` | `True` | `False` | — |
| `DISCORD_WEBHOOK_URL` | 선택 | 선택 | 추천 전달 / 배치 알림 |
| `LITE_DB_URL` (빌드 인자) | — | Release 다운로드 URL | Dockerfile이 이미지에 DB를 구움 |

## 4. 자주 나오는 문제

| 증상 | 원인 / 조치 |
|---|---|
| Koyeb Build에서 `curl ... app_lite.db` 실패 | STEP 2 미완(Release 자산 없음) 또는 `LITE_DB_URL` 오타. 저장소가 private면 Release 자산도 인증 필요 → public으로 두거나 자산 URL에 토큰 |
| 배포는 됐는데 `/` 가 200(리다이렉트 안 됨) | `APP_PROFILE` 이 `web` 로 안 들어감. Koyeb 환경변수 오타 확인 |
| 가상매매가 재배포마다 사라짐 | `PAPER_DATABASE_URL` 미설정(Turso 폴백 중). STEP 3 진행 |
| `sqlite+libsql` 연결 에러 | `deploy/requirements-web.txt` 의 `sqlalchemy-libsql` 주석 해제 후 재빌드 |
| Actions `Upload lite DB` 권한 오류 | STEP 1의 Workflow permissions = Read and write 미적용 |
| Discord 알림이 안 옴 | Secret `DISCORD_WEBHOOK_URL` 미등록 (로컬 `.env` 와 별개) |

## 5. 권장 진행 순서 (한눈에)

```
STEP 0  Claude: git push origin master              (승인 필요)
STEP 1  GitHub: Actions 권한 Read and write
STEP 2  GitHub: Release(lite-db)에 app_lite.db 업로드
STEP 3  Turso : 가입·DB·토큰  (건너뛰면 prop 비영속)
STEP 4  GitHub: Secrets 등록
STEP 5  Koyeb : 앱 생성 + 빌드인자 LITE_DB_URL + 환경변수
STEP 6  Koyeb : 배포 훅 생성 → GitHub Secret
STEP 7  GitHub: Actions 수동 실행 1회
STEP 8  확인  : 접속·리다이렉트·PWA·JSON 백업
STEP 9  로컬  : (선택) .env 에 PAPER_DATABASE_URL
```
