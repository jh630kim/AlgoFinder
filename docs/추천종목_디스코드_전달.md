# 추천종목 디스코드 전달 기능

## 1. 목적

투자제안(PC) · 투자제안(모바일) 화면에서 현재 조회된 추천 기준일의
**매수 추천 종목 표 전체**와 **보유 종목 매도 추천 시그널**을
버튼 한 번으로 함께 디스코드 채널에 전달한다.

---

## 2. 요구사항

- 두 화면(`templates/proposal.html`, `templates/proposal_mobile.html`) 모두
  "🟢 퀀트 전략별 TOP 1~3위 매수 추천 종목 표" 카드 헤더의
  **"🛒 수동 매수 실행" 버튼 바로 왼쪽**에 **"📤 추천종목 전달"** 버튼을 추가한다.
- 버튼 클릭 시 현재 `추천 기준일`의 매수 추천 종목 목록과 매도 추천 시그널 목록을 한 메시지에 디스코드 웹훅으로 전송한다.
- **매수 추천** 전송 대상은 추천표 전체.
- **매도 추천** 전송 대상은 투자제안 "🔻 보유 종목 매도 추천 시그널 감지 표"에 표시되는 항목 전체(투자제안 계좌 `prop` 보유 종목 중 기준일에 매도 신호가 포착된 종목).
- 같은 종목이 여러 전략에 중복 포착되면 **한 줄로 병합**한다.
  - 알고리즘 칸에 전략별로 `S1(35%), S4(50%)` 형식(콤마 구분)으로 표기한다.
  - 괄호 안 확률은 각 전략의 상승 확신 확률(%).
- 알고리즘 라벨은 내부 전략키를 그대로 사용한다: `S1`, `S1a`, `S1b`, `S1c`, `S2`, `S3`, `S4`, `S5`.
- 매수·매도 중 한쪽만 있으면 그쪽만 전송하고, <span style="color:red">둘 다 없으면 `매수/매도 추천 종목이 없습니다` 문구를 디스코드로 발송한다(미발송 아님).</span>
- 모든 연산·포맷팅·검증은 백엔드가 담당한다(Thin Client 규칙).

---

## 3. 디스코드 메시지 포맷

### 매수 추천 — 한 줄 포맷

```
순위 | (코드)종목명 | 추천가(종가) | 알고리즘(확률), 알고리즘(확률) ...
```

- **순위**: 병합 후 목록 순서. 종목의 최고 상승 확신 확률 내림차순으로 1부터 부여.
- **추천가(종가)**: 종목당 1개 값(전략과 무관하게 동일). 천단위 콤마 + `원`.
- **알고리즘(확률)**: 해당 종목을 포착한 전략들을 확률과 함께 나열.

### 매도 추천 — 한 줄 포맷

```
순위 | (코드)종목명 | 보유수량 | 현재가(등락률) | 매도 사유
```

- **순위**: 매도 시그널 목록 순서대로 1부터 부여.
- **현재가(등락률)**: 기준일 종가, 괄호 안은 매수가 대비 등락률(%).
- **매도 사유**: 뱃지(`전략 매도 신호: Sx` / `🔻 손절선 -5%` / `🎯 익절선 +10%`)와 사유 요약.

### 전체 메시지 예시

```
📈 매수 추천  |  기준일: 2026-08-27 (평가일: 2026-08-27)

 1 | (005930)삼성전자    | 71,200원 | S1a(63.5%), S1(58.2%)
 2 | (000660)SK하이닉스  | 168,000원 | S3(61.0%)
 3 | (247540)에코프로비엠 | 92,400원 | S4(55.7%), S5(51.3%)
총 3개 종목
```
```
🔻 매도 추천  |  기준일: 2026-08-27

 1 | (068270)셀트리온 | 10주 | 172,000원 (-6.1%) | 🔻 손절선 -5% / 전략 매도 신호: S1
 2 | (035420)NAVER   | 5주  | 210,000원 (+11.3%) | 🎯 익절선 +10%
총 2개 종목
```

<span style="color:red">매수·매도 모두 0개일 때도 아래 형태로 발송한다(미발송 아님).</span>

```
📭 추천 없음  |  기준일: 2026-08-27

매수/매도 추천 종목이 없습니다
```

- 정렬·가독성을 위해 매수·매도 각각 코드블록(``` ```)으로 감싸 전송한다(둘 다 있으면 한 메시지에 이어서).
- 매수·매도 중 한쪽만 있으면 그쪽만 전송한다. <span style="color:red">둘 다 없으면 `매수/매도 추천 종목이 없습니다` 한 줄을 디스코드로 발송한다.</span>

## 4. UI 변경

### PC (`proposal.html`)

- 위치: 추천 표 카드 헤더 우측 버튼 영역, "🛒 수동 매수 실행" 왼쪽.
- 라벨: `📤 추천종목 전달`
- 스타일: 인디고/블루 계열 그라데이션(수동 매수 버튼의 초록과 시각적으로 구분).

### 모바일 (`proposal_mobile.html`)

- 동일 위치. 모바일 버튼 규격(축소 패딩·폰트)에 맞춘다.
- 헤더 폭이 좁을 때 버튼이 겹치지 않도록 버튼 영역에 `flex-wrap` 허용.

### 동작 (`static/js/proposal.js`, PC/모바일 공용 컨트롤러)

1. 클릭 시 확인창: "현재 기준일의 매수·매도 추천을 디스코드로 전달할까요?"
2. 확인 시 버튼 비활성화 + 라벨 "전달 중…" (중복 전송 방지).
3. 현재 `recTargetDate` 값으로 전달 API 호출.
4. 결과 `alert`: 성공 시 "디스코드로 매수 N건 · 매도 M건을 전달했습니다.", 실패 시 오류 메시지.
5. 버튼 라벨·활성 상태 원복.

## 5. 백엔드 구조

### 5.1 디스코드 발송 서비스 (`DiscordNotifier`)

- 위치: `backend/app/services/discord_notifier.py` (주 객체 1개, 한글 독스트링).
- 역할: 전달받은 텍스트 메시지를 `.env`의 `DISCORD_WEBHOOK_URL`로 POST.
- 인코딩(중요, CLAUDE.md 5.3): 본문을 **UTF-8 바이트 배열**로 전송해 한글 깨짐을 방지한다.
- 반환: 성공/실패 여부(및 실패 사유).
- 웹훅 URL 미설정 시: 에러 반환(발송 시도 안 함).

### 5.2 추천종목 전달 엔드포인트

- `POST /api/proposal/notify-recommendations` (`backend/app/api/routes_paper.py`).
- 요청 body: `{ "target_date": "YYYY-MM-DD" | "YYYYMMDD" }`
- 처리 순서:
  1. `target_date` 정규화(기존 `_ymd` 규칙 재사용).
  2. `ProposalAdvisorCache` 로 매수 추천 목록 재조립(`/api/recommended-stocks` 와 동일 소스).
  3. **종목코드 기준 병합**: 같은 코드는 한 항목으로, 전략 목록 `[(전략키, 확률), ...]` 누적 → 최고 확률 내림차순 정렬 → 순위 부여.
  4. 투자제안 계좌(`prop`) 보유 종목을 `PaperTradingRepository` 로 조회하고, `ProposalAdvisorCache.build_portfolio_view` 로 기준일 매도 시그널(`sell_signals`)을 산출(`/api/paper-trading/portfolio` 와 동일 소스).
  5. 매수·매도 각각 3장 포맷으로 메시지 블록 생성(항목이 있는 블록만). <span style="color:red">둘 다 비면 `매수/매도 추천 종목이 없습니다` 블록 생성.</span>
  6. `DiscordNotifier` 로 발송.
- 응답: `{ "status": "success", "buy_count": N, "sell_count": M }` / 실패 시 `{ "status": "error", "message": "..." }`
- <span style="color:red">매수·매도 모두 0개: `매수/매도 추천 종목이 없습니다` 메시지를 디스코드로 발송하고 `{ "status": "success", "buy_count": 0, "sell_count": 0 }` 을 반환한다.</span>

## 6. 환경변수 · 배포

- 웹훅 URL은 `.env` 의 `DISCORD_WEBHOOK_URL` 로 관리한다(코드 하드코딩 금지, CLAUDE.md 규칙 7).
- `config.py` 는 이미 `os.environ` → pydantic `Settings` 로 읽으므로 코드 변경 불필요.
- 저장소에는 `.env.example`(키 이름만, 값 빈칸)을 추가해 배포 시 참고 자료로 제공한다.
- **웹서버(PythonAnywhere) 적용**: `.env` 는 `.gitignore` 대상이라 배포되지 않으므로,
  서버의 프로젝트 루트에 `.env` 파일을 직접 1회 생성하고 `DISCORD_WEBHOOK_URL` 값을 채운다.
  (또는 WSGI 설정/Bash 콘솔에서 환경변수를 지정 — 값 노출 때문에 비권장.)

  디스코드 채널 수신 및 메시지 포맷(매수 순위·병합·확률 표기, 매도 사유·등락률 표기<span style="color:red">, 추천 없을 때 안내 문구 발송</span>)을 육안 확인 후 결과 보고.
